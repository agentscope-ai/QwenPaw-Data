# Host application and Console consumer contracts (candidate v1)

These contracts target the coordinated 0.4.1 release and are not part of the published 0.4.0 packages. Consumers should install matching Host-core and Console versions from the verified release wheels. Before publication, build from the reviewed source revision and pin the resulting wheel by hash.

## Trusted installation boundary

Register an **instance** inheriting `qwenpaw_data.host.core.applications.HostApplication` in the `qwenpaw_data.applications` entry-point group. The entry-point name is the session `agent_id`; `api_version` must be 1. Duplicate names and unsupported contracts fail startup/discovery. Only deployment-installed Python is loaded; browser payloads cannot register code. Unknown IDs keep the native builder path.

The extension can declare `required_skills`, `required_mcps`, `wrapped_mcps` and `mcp_defaults`. Skills and MCPs are discovered through `qwenpaw_data.skill_packs` / `qwenpaw_data.mcp_presets`; the native configuration stores remain authoritative. A disabled required capability fails rather than bypassing the stored configuration.

Hooks: `register(app)` adds authenticated domain routers; `startup(app, cleanup)` initializes domain services; `prepare_run(context, envelope)` initializes per-run `application_state`; `prepare_turn(context, turn)` returns a turn; `tools(context)` contributes native toolkit tools; `close_run(context)` releases resources. `handle_external(context, required)` returns `None` for ordinary native question handling. Optional `session_summaries(db, identity, sessions)` and `session_patched(db, identity, session, patch)` hooks handle downstream summary/projection needs. Routers must enforce native identity and session access checks themselves.

Use the run's native clarification facility for domain decisions, validation and timeouts. Host retains the durable answer command, consumption, cancellation and event lifecycle; extensions must not create a parallel answer queue. Domain validation must run again when a queued answer is consumed because its state may have changed since HTTP submission.

## Presentation and replay

```json
{"presentation":{"extensions":{"org.example.analysis":{"version":1,"data":{"choices":["a","b"]}}}}}
```

Extension versions must be positive integers; each payload is a JSON object. Host stores/replays the namespace without importing its domain schema. The consumer validates its own data and ignores unsupported versions. Historical opaque presentation fields remain round-trippable; this compatibility does not make them public typed domain fields. Session list summaries are under `extensions[agent_id]`.

Clients use native `/api/v1/sessions`, paginated snapshots (`limit`, `before_sequence`, `has_more`), traces and chat SSE. Resume with the native event sequence cursor; reconcile persisted state after disconnect. No React/Console internal imports are required. The frontend package is not an SDK.

## Gateway extension policy

Console `create_app` accepts deployment-owned `application_routes` tuples of `(regex, methods)`, `document_routes` regexes and optional exact `frontend_routes`. Application route patterns are relative to `/api/v1/`; document patterns match the full path including `/api/v1/`. Paths still pass normalization, method allowlists and origin guards. Same-origin document navigation is permitted only for registered document patterns; the gateway preserves upstream CSP and adds sandbox restrictions. Never pass untrusted user patterns here. Domain code/assets remain outside the Console wheel.

`GET /api/v1/console/identity` exposes only the already-authenticated principal's identity, workspaces and capabilities. It uses normal authorization; it does not accept a browser-supplied identity as proof of authentication. A host using delegated service identity must authenticate the caller, select its scope and keep delegation material server-side.

## Official embed runtime configuration

`window.QWENPAW_DATA_CONSOLE` supports `api_base_url`, `auth: {mode: 'native' | 'host', api_base_url, login_url?}`, and `databridge: {base_path?, api_base_url?, open_in_console?}`. Keep API prefixes same-origin through a host gateway. Host-auth mode retains the authenticated principal but hides native account switching. Capability flags also guard direct routes; they are UI controls, not replacements for server authorization. Use the build generated by `scripts/build_console.py`, packaged as `static/chat-embed/`.

Native Skills and MCP settings accept `?agent_id=...` (or the same query inside an embed hash route). The generic Agent profile control applies that scope to reads, writes and revision/tool operations; changing scope remounts page state to discard open editors. No domain-specific profile list is shipped.
