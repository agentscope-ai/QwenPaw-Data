# 排版规范

本文档定义报告页面的视觉风格与排版规则。

**适用范围**：普通 BI 分析场景参照执行，文中的尺寸、行数、布局数值是默认值，按数据
实际情况调整即可。**报告复现模式下，`format_spec.json` 的
`source_css` / `dom_contract` 优先级更高，本文档只补它们未定义的部分**；两者冲突时
一律以 `format_spec.json` 为准。下文各节里标了「复现模式」的段落就是这类冲突点。

原因很具体：原报告的 CSS 会被整段透传进页面，它里面的选择器只认它自己的类名。
把 `.grid2` 换成 `rp-grid-2`、把 `.pos` 换成 `rp-pos`，透传进来的规则一条也命中不了。

## 0. 页面风格

报告是一张浅色、留白充足的数据页。样式全部由 `resources/theme.css`（`rp-*` 类）提供，
blocks 自动套用，不需要手写。

**页面结构**（从上到下）：

| 区域 | 内容 | 来源 |
| --- | --- | --- |
| 标题区 | 报告标题、可选的一条 KPI 带、生成日期（不放摘要 / 结论，结论写在第一章） | `--report-title`、`"type": "hero"` 的 section |
| 编号章节 | 每章一个编号标题（`01`、`02`…，药丸色按蓝 / 青 / 紫 / 橙循环）+ 章标题 + 可选的右侧短副标题 | 每个 section 的 `title`、`subtitle` |
| 数据卡片 | 每个表 / 图 / 构成条各占一张白底圆角卡片，卡头是标题 + 可选的一行副标题 | 块的 `title`、`subtitle` |
| 页脚 | 居中灰色一行 | 骨架自带 |

所有章节按顺序纵向排列、全部可见，不做 tab 切换。

**只加载样式，不加内容**：标题区不加标语 / 栏目名之类的装饰文字；不加「数据快照」
「口径与数据说明」这类说明区块；页脚不写数据时间、生成方式。副标题只写读懂这张卡
必须知道的信息（单位、周期、排序方式），能省就省。

**色板**（`theme.css` 的变量）：

| 用途 | 色值 |
| --- | --- |
| 主色 / 下降 | 蓝 `#1C54E3`（深 `#0423DA`） |
| 辅色 | 青 `#00CEC9`、紫 `#7347FF`、橙 `#fb6a3c` |
| 上升 | 绿 `#1e8e3e` |
| 成本类上升 | 红 `#C62828` |
| 文字 | 主 `#10141c` / 次 `#454b58` / 弱 `#8a909c` |
| 线与底 | 分隔线 `#ebedf1`、浅底 `#f7f8fb` |

ECharts 系列色按 蓝 → 青 → 紫 → 橙 的顺序取用。

> **复现模式**：本节整体不适用，页面层级、色板、字体一律按 `format_spec.json`。

## 1. 展示形式与布局

### 展示形式选择

每份数据严格选一种展示形式，禁止重复展示同一份数据。

**快速对照（按数据特征）**:

| 分析场景 | 数据特征 | 推荐可视化 |
|----------|----------|------------|
| 当前状态 | 1-4 个关键指标 | KPI 带（一行，数值 + 单位 + 环比） |
| 趋势变化 | 波动类 / 时序数据 | 折线图或柱状图（当前周期高亮）；量与率同看时用柱 + 线双轴 |
| 各部分占比 | 一个总量拆成 2-6 类 | 构成条（`stackbar`）或环形图 |
| 各部分占比 | 占比 > 6 类 | 取 Top 8 + 环形图，其余合并为「其他」 |
| 排名对比 | 多主体同指标 | 横向条形图 |
| 转化流失 | 漏斗步骤数据 | 漏斗图 |
| 逐行细节 | 指标按非时间维度拆解 | 表格 |
| 两变量关系 | 双数值变量 | 散点图 |

对于行数 < 4 或列数 < 3 的表格，改用 KPI 带展示。KPI 有对比基期时附上变化（如环比）。

**详细规范（按分析任务类型）**: 标注"✦ 支持切换"的场景可选做图表/表格双视图，列出的是表格视图的建议列：

| 分析任务类型 | 推荐图表 | 使用要点 | 双视图 |
| --- | --- | --- | --- |
| 转化漏斗（注册→激活→付费等多环节） | ECharts 漏斗图（`type: 'funnel'`） | 从大到小排列各环节，标注每步转化率和绝对流失量 | ✦ 表格列：环节名 / 数量 / 转化率 / 流失量 |
| 时间趋势 / 异常检测 | 折线图或柱状图，叠加 `markPoint` / `markLine`；当前周期用 `highlight` 高亮 | 标注异常点、骤升骤降 | ✦ 表格列：日期 / 当期值 / 环比变化 / 备注 |
| 量与率同看（消耗 + 环比、客户数 + 占比） | 柱 + 线双轴（线系列 `axis: "right"`） | 柱为量、线为率，两轴各自单位 | ✦ 表格列：周期 / 量 / 率 |
| 多维度量级对比（排名、Top N） | 横向条形图（条目 > 8 时必选） | 按值降序排列，Top 10 后聚合为「其他」 | ✦ 表格列：维度名 / 数值 / 占比 |
| 时间 × 维度双向对比（本期 vs 上期） | 分组柱状图或双折线图 | 两组数据用不同颜色，图例置顶 | ✦ 表格列：维度 / 本期 / 上期 / 变化率（颜色标注） |
| 占比分析（2–6 类） | 构成条或环形图 | 超 6 类时取 Top 8，其余合并为「其他」 | ✦ 表格列：类别 / 数量 / 占比 |
| 留存 / 队列分析 | 热力色表格（蓝色深浅标注单元格） | 行为入组时间，列为留存周期，颜色深浅表示留存率 | — （本身即表格，无需切换） |
| 多指标综合评估 | 雷达图（`type: 'radar'`） | 适合 5–8 个归一化指标，维度过多时改用表格 | ✦ 表格列：指标名 / 当期值 / 基准值 / 得分 |
| 归因 / 维度贡献拆解 | 瀑布图（堆叠柱状图模拟）或分组表格 | 正贡献绿色，负贡献蓝色，末行为合计 | ✦ 表格列：归因维度 / 贡献值 / 贡献率 / 方向 |
| 1–4 个关键指标 | KPI 带（数值 + 单位 + 环比） | 每格至少包含 2 个维度，不只放一个大数字 | — （KPI 不切换） |
| 指标按非时间维度拆解（4 列以上） | 表格 | 行数 < 4 或列数 < 3 时改 KPI | — （本身即表格，无需切换） |

### 布局决策

核心原则：空间利用率最大化，避免不必要的纵向滚动，优先并排展示。

| 布局类型 | 适用条件 | blocks 写法 | CSS 类名 |
| -------- | -------- | ----------- | -------- |
| 2 个等宽并排 | 两个数据块都较简单（表列数 < 8，图表数据点 ≤ 12） | `grid` + `cols: 2` | `rp-grid-2` |
| 左宽右窄 | 主图 / 主表 + 一个小的构成或补充块 | `grid` + `cols: "2:1"` | `rp-grid-2-1` |
| 3 个并排 | 三个数据块都较简单（表列数 < 6） | `grid` + `cols: 3` | `rp-grid-3` |
| 顺序堆叠 | 任一数据块较复杂（大表格、多系列图表） | 直接按顺序写块 | 每张卡片带 `rp-stack` |

> **复现模式**：上表的 `rp-*` 类名不适用，改用 `source_css` 里原报告自己的栅格类。
> 例如某份原报告用 `.grid2 { display:grid; grid-template-columns:repeat(auto-fit,
> minmax(430px,1fr)); gap:16px }`，它的自适应行为与 `rp-grid-2` 并不等价，
> 换掉就改了布局。

混排布局示例：

- 左表（4-6 列）+ 右图（环形图/单线趋势图）：用 `cols: 2`
- 左侧排名条形图 + 右侧构成条：用 `cols: "2:1"`
- 左图 + 中图 + 右表（4 列以内）：用 `cols: 3`
> KPI 带不和其他图表并排；全报告最重要的一条 KPI 带放进标题区（`"type": "hero"`）

### 并列高度协调

并排展示的数据块高度应对齐，确保视觉平衡：

- 并列 ECharts 图表：两个容器设置相同的 `height` 值（`grid` 自动处理）
- 并列表格：两边行数差距 ≤ 2 行，多出的行用滚动容器截断
- 表格与图表并列：表格外层用 `style="max-height:Xpx"` 的滚动容器对齐图表高度
- 同一行的卡片自动等高

### 二级维度数据

对于二级维度下拆的数据，每个一级主体独立展示，配小表格展示其二级维度指标和一句关键结果，在整体下方给出总体的数据描述和解读。

## 2. 图表规范

**尺寸与方向**：

- 图表高度参考数据点数量：≤ 5 个约 `240px`，6-12 个约 `300px`，13+ 个约 `340px`
- 图表占满所在卡片的宽度；并排时由栅格分配
- 条目 > 8 时使用横向条形图（`yAxis` 为 category，`xAxis` 为 value）

**ECharts 配置**（blocks 自动生成，手写时照此）：

- `grid`：`{ top: 36, right: 24, bottom: 24, left: 16, containLabel: true }`，避免内部大量留白
- 坐标轴：标签 `#8a909c` 11px，轴线 `#e3e7ee`，不画刻度，网格线 `#eef1f5`
- 图例放在顶部：`legend: { top: 4, icon: 'roundRect' }`，图例不得遮挡重叠；单系列不显示图例
- 数据标签：数据点 ≤ 12 且系列 ≤ 2 时在柱顶 / 点上标出格式化后的数值；柱 + 线双轴时只标柱
- 柱：单系列为蓝色竖向渐变、顶部圆角 `[6,6,0,0]`；需要突出当前周期时其余柱用浅蓝
  `#c7d4f2`、当前柱用蓝紫渐变
- 横向条形：蓝色横向渐变、右端圆角 `[0,8,8,0]`，数值标在条右侧（蓝色加粗）
- 折线：圆点、线宽 2.5，不平滑；双轴时右轴折线用青色，右轴不画网格线
- 环形图：`radius: ['45%','70%']`，扇区间留 2px 白边
- tooltip：白底、浅边框、柔和阴影
- 同一张图里的对比系列（本期 vs 上期、分组柱）放在同一实例的多个 series 中；互不相关的图表用独立实例
- 容器 id 以章节标题拼音缩写开头，避免 id 冲突
- 仅当有可结构化数值数据时才生成 ECharts 图表，否则用表格或文字
- 每个实例初始化后注册到全局数组：

```javascript
window.__echartsInstances = window.__echartsInstances || [];
var chart = echarts.init(document.getElementById('your-chart-id'));
window.__echartsInstances.push(chart);
```

## 3. 表格规范

表格（`rp-table`）占满卡片宽度，12.5px 字号，`8px 12px` 内边距，表头为浅底灰色小字。

- **数值列**右对齐、等宽数字；**首列**（名称）加粗深色
- **斑马纹**：普通表格隔行浅底
- **长表格**（超过 10 行）：放进带边框的滚动容器（默认 `max-height:360px`），数据完整
  渲染不截断；表头改为深色并吸顶，表头可点击排序
- **明细清单**：可加序号列（`rank`）和搜索框（`search`）；分类字段（行业、类型、状态）
  用药丸标签（`tag`）展示，不要用整列文字
- **合计行**在 `<tfoot>`，浅蓝底加粗；排序时「其他」行和合计行保持在末尾
- **下钻表**：可展开的行首有圆形 `▸` 按钮，展开后子表缩进显示在浅底行里

```html
<div class="rp-table-wrap scroll" style="max-height:360px">
  <table class="rp-table zebra dark">
    <thead>...</thead>
    <tbody><!-- 渲染所有行，不截断 --></tbody>
  </table>
</div>
```

- 普通 BI 分析：不要用 `<details>` 折叠，也不要拆分为多个子表——滚动容器已经解决了
  高度问题，折叠会让数据「看上去不存在」。
- **复现模式**：原报告若用 `details.panel` 之类的折叠容器，就照 `dom_contract` 里的
  结构写，本条不适用；滚动容器也用原报告自己的（例如 `.tblwrap` 已经带
  `overflow-x:auto`），不要再套一层 `rp-table-wrap`。

**内容规则**：按表格用途分两类，不要一刀切。

| 表格用途 | 回答的问题 | 行数处理 |
| --- | --- | --- |
| 排名 / 占比类 | 「谁最大」 | 按指标值降序，默认展示 Top 10，剩余聚合为一行「其他（N 项）」，聚合值取合计或均值（视指标类型） |
| 明细 / 清单类 | 「每一项是多少」 | **完整渲染，不聚合、不删行**，用滚动容器 |

明细 / 清单类包括：下钻明细、UID / 实体级清单、留存矩阵、对账表。

> **复现模式：两类都不聚合。** 复现的验收标准是数值逐项对齐，原报告有多少行就写
> 多少行；聚合会让明细行消失，直接判不通过。

## 4. 数据表述与颜色

**文字表述**：

- **单位**：数据文件里的数默认原样加 `%`（贡献度、占比、渗透率、环比/WoW 等）；人数/金额变动不加百分号。`pt` 只用于「率值从 A% 变到 B%」的差值，不要把 `%` 改成 `pt`
- KPI 的单位写进 `unit`（显示为数值后的小字），不要拼进数值或标签
- 禁用模糊词（「显著增长」「大幅下降」「略有波动」「基本稳定」等），必须给出具体数值
- 禁止未经证实的发散式推测

**数字颜色标注**：

| 数字类型  | 普通 BI 分析                                   | 复现模式 |
| --------- | ---------------------------------------------- | --- |
| 关键数值  | `<span class="rp-key">`（深色加粗）            | 用 `source_css` 里对应的强调类 |
| 下降/负面 | `<span class="rp-neg">`（蓝色加粗）            | 用原报告的负向类 |
| 上升/正面 | `<span class="rp-pos">`（绿色加粗）            | 用原报告的正向类 |
| 成本类上升 | `<span class="rp-bad">`（红色加粗，`color: sign_inv`） | 用原报告的对应类 |

> **复现模式**：类名必须取自 `source_css`，不要换成 `rp-*` 类。例如某份原报告里
> 正向是 `.pos { color:var(--green) }`、负向是 `.neg { color:var(--red) }`、比率单元格
> 底色高亮是 `.rate-hl { background:#fffbeb }`，那就用这三个。
>
> 还要注意嵌套限定：同一份原报告里数值右对齐是 `.tbl th.r, .tbl td.r`，意味着
> `class="r"` 必须同时满足「在 `.tbl` 表格内」+「挂在 `<th>`/`<td>` 上」才生效；
> 写到 `<span class="r">` 上不会右对齐。`dom_contract` 里的 `selector` 就是用来
> 告知这类限定关系的。

**不写过程信息**：不在卡片里标数据来源文件链接、SQL、计算步骤、校验结果或版本变化，
这些在聊天回复里交代（完整清单见 `SKILL.md`「报告写什么、不写什么」）。口径确需说明时，
在对应指标旁写一行小字：

```html
<div class="rp-note">活跃 = 当周净 GAAP &gt; 0 的 uid</div>
```

## 5. 卡片模板

针对每个主题产出的 HTML 卡片是片段形式，最终会被嵌入完整的报告页面中，因此只输出卡片内容，不包含 `<html>`、`<head>`、`<body>` 等页面标签。避免输出空 DOM 节点。
章节编号标题由骨架按 section 的 `title` 生成，片段里不要再写一遍章标题。

页面里的资源全部自包含（离线可用）：报告主题内联为 `resources/theme.css`，Tailwind
工具类按需裁剪后内联为 `resources/report.css`，Bootstrap Icons 字体以 base64 内联为
`resources/icons.css`，ECharts 内联本地 `resources/echarts.min.js`，图表兜底运行时是本地
`resources/chart_fallback.html`。下文的 `rp-*` 类都在 `theme.css` 里；需要零星的 Tailwind
工具类时，只要出现在 `report.css` 里就能生效，新增后用 `scripts/build_report_css.py` 重新
生成。**复现模式下优先用 `source_css` 里的原报告类名**。

**声明式 blocks 与本节的对应**：普通 BI 分析不必手写下面的模板，在 `sections_*.json` 里写
`blocks`（见 SKILL.md 步骤 3），`report_builder.py` 会按本节的类名生成同样的卡片。
图表类型到 `chart.kind` 的映射：

| 上文图表类型 | `chart.kind` |
| --- | --- |
| 折线图（趋势 / 异常检测，叠加 `markPoint` / `markLine`） | `line` + `mark` |
| 柱状图（单维对比，当前周期高亮） | `bar` + `highlight` |
| 柱 + 线双轴 | `bar`，线系列 `{"type": "line", "axis": "right"}` |
| 分组柱状图 / 双折线（本期 vs 上期） | `grouped_bar`（或多个 `series` 的 `line`） |
| 横向条形图（排名、Top N） | `hbar` + `top_n` |
| 饼图 / 环形图（>6 类自动合并「其他」） | `pie` |
| 漏斗图 | `funnel` |
| 散点图 | `scatter` |
| 雷达图 | `radar` |
| 构成条 | `stackbar` 块 |
| 热力色表格（留存 / 队列） | `heatmap_table` 块 |
| 下钻表 | `drill_table` 块 |

> 以下模板是**普通 BI 分析**手写 `html_fragment` 时的默认结构。报告复现模式不要套用，
> 改按 `dom_contract` 里的结构写。

**核心结论**（≤60 字，禁用模糊词，必须包含具体数值；放在章节最前）：

```html
<div class="rp-lead">
  <!-- 模板：[指标][关键数值]，环比[变化描述]，主要受[因素1, 因素2, ...]影响
       颜色：关键数值 rp-key，下降 rp-neg，上升 rp-pos -->
  W43 净 GAAP <span class="rp-key">30,390.05</span> 万元，环比 <span class="rp-neg">-1.66%</span>
</div>
```

**KPI 带**（有基期时附环比；`k1`–`k4` 决定顶边颜色）：

```html
<div class="rp-kpi-band">
  <div class="rp-kpi k1">
    <div class="rp-k-label">指标名称</div>
    <div class="rp-k-num">30,390.05<small>万元</small></div>
    <div class="rp-k-foot">环比 <span class="rp-neg">-1.66%</span></div>
  </div>
  <!-- 更多 KPI（同一行） -->
</div>
```

**数据卡片**（一张卡片一个表 / 图；并排时外层套 `rp-grid-2` / `rp-grid-2-1` / `rp-grid-3`，
卡片去掉 `rp-stack`）：

```html
<div class="rp-card rp-stack">
  <div class="rp-card-top"><div>
    <div class="rp-card-h">卡片标题</div>
    <div class="rp-card-s">可选副标题：单位 / 周期</div>
```
