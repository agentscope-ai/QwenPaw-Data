# 草稿

`draft.md` 通过 `rr update-section --content-file` 整篇落盘。CLI 不改写正文。

## 版式（R6）

- 标题层级、表格、列表和句子顺序跟原报告该节一致。
- 不把分析过程、SQL 或取数说明写进正文。那些留在 `queries/`、`data/` 和 `comparison.json`。
- 定时运行以 `exemplar.md` 为模板：`〔数〕` 逐个换成本期算出的数，标题编号和「1. 2. 3.」这种列表序号保留。

## 缺口块（R7）

客观补不上的缺口放在草稿最上方，标题必须是：

```markdown
## 复现差异与数据缺口说明

- 【数仓缺口】订单表没有退款标记。本期沿用全量订单，收入会偏高。来源：表结构。
- 【语义缺口】「活跃」没有统一口径。本期按近 30 日登录计。来源：推测。
```

标签只用 `【数仓缺口】`、`【语义缺口】`、`【无法复现】`。每条写清缺什么、本期怎么替代、对结论的影响、来源。

不要把还能问用户的数值差、原报告数字、偏差率写进这个块。`【无法复现】` 会使证据门禁失败，基线不能靠它放行。导出时这个块会进入定时指令的「已知缺口」，里面的业务数字会变成 `〔数〕`。

## 口径披露（R3）

正文里每条口径单独一句，贴一个标签：

```markdown
营业收入为本期订单汇总，口径来源：重算。
渠道拆分含税，口径来源：用户确认。
活跃按近 30 日登录估算，口径来源：推测。
```

`重算` 表示查询和数据文件已经落盘。`用户确认` 表示理由来自用户的回答，并应写入 `apply-comparison --reason`。`推测` 不能冒充另外两个。没有本次计算、也没有用户确认时，写 `原报告`。

## 例子

原文章节是「本月营业收入 1234.5 万元，同比增长 12.3%」。重算得到 1300.0 和 11.0%，且用户接受了含税口径：

```markdown
## 复现差异与数据缺口说明

- 【数仓缺口】缺少退款标记。本期沿用全量，收入偏高。来源：表结构。

## 一、总体概览

本月营业收入 1300.0 万元，同比增长 11.0%。口径来源：用户确认。
```

定时运行的 exemplar 会变成「本月营业收入 〔数〕 万元，同比增长 〔数〕」，标题「一、」保持不动。
